**Mode-aware caption routing wired through service layer, API router, and JoyCaption subprocess — caption_mode drives backend selection and post-processing pipeline for all 5 modes.**

## Accomplishments

- Replaced style-based routing with `caption_mode` routing in `caption_image_for_project()` — booru_tags and context_only_tags route to WD Tagger (with appearance filtering for context_only), all other modes with VLM config route to VLM + pipeline
- Added `get_caption_mode_for_project()` (global config priority over profile mapping) and `_resolve_token_budget()` (vlm_config > profile > 150)
- Updated `build_vlm_config_from_global()` to pass `caption_mode` and `max_tokens` from global config to all VLM providers (lm_studio, nanogpt, gemini)
- Parameterized JoyCaption runner script with `--mode` arg and `MODE_PROMPTS` dict covering all 5 modes
- Added `appearance_blacklist_extra: list[str]` to `CaptionProviderConfig` — user-added appearance tags merged with `DEFAULT_APPEARANCE_BLACKLIST` at JoyCaption pipeline call site
- Applied `apply_joycaption_pipeline` in `_run_joycaption_subprocess` after receiving each caption from subprocess
- Updated PUT/GET `/captions/config` to round-trip `caption_mode`, `max_tokens`, and `appearance_blacklist_extra`
- Added 20 new tests across 3 test files; full suite: 1382 passed, 4 skipped (no regressions)

## Decisions Made

- `caption_style_override` in manifest is intentionally ignored in `get_caption_mode_for_project` — mode is a global concern per CONTEXT.md
- `apply_vlm_pipeline` called inside `caption_image_for_project` rather than in the router — keeps post-processing close to generation, router doesn't need to know about pipeline
- JoyCaption runner script does basic cleanup inline (robustness in subprocess), parent process applies full `apply_joycaption_pipeline` post-processing
- `context_only_tags` without VLM: use `_filter_appearance_tags` + `_dedup_tags` (string-based pipeline functions) on WD Tagger output
