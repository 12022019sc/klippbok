       ```typescript
       const CAPTION_MODES: { value: string; label: string }[] = [
         { value: 'context_only_tags',    label: 'Context Only (Tags)' },
         { value: 'context_only_natural', label: 'Context Only (Natural)' },
         { value: 'booru_tags',           label: 'Booru Tags' },

         { value: 'straightforward',      label: 'Straightforward' },
       ]
       ```
       Order: Context Only modes first (primary use case), then Booru, then NL modes.

    3. **Add mode dropdown to expanded config body** in `ProviderConfigSection.tsx`:
       Place BEFORE the provider dropdown (mode is more important — user decision: "dropdown in the collapsible config section next to provider dropdown"). Use the existing `provider-config-field` / `provider-config-label` / `provider-config-select` CSS classes for consistency.
       ```tsx
       <div className="provider-config-field">
         <label className="provider-config-label">Caption Mode</label>
         <select
           className="provider-config-select"
           value={local.caption_mode}
           onChange={(e) => setLocal({ ...local, caption_mode: e.target.value })}
         >
           {CAPTION_MODES.map((m) => (
             <option key={m.value} value={m.value}>{m.label}</option>
           ))}
         </select>
         <span className="provider-config-hint">
           Context Only modes exclude appearance (for Character LoRA)
         </span>
       </div>
       ```

    4. **Add max-tokens field** in `ProviderConfigSection.tsx`:
       Place after mode dropdown, before provider dropdown. Use `provider-config-input` class.
       ```tsx
       <div className="provider-config-field">
         <label className="provider-config-label">Max Tokens</label>
         <input
           type="number"
           className="provider-config-input"
           value={local.max_tokens ?? ''}
           onChange={(e) => setLocal({
             ...local,
             max_tokens: e.target.value ? parseInt(e.target.value, 10) : null,
           })}
           placeholder="Auto (from model profile)"
           min={10}
           max={500}
         />
         <span className="provider-config-hint">Leave blank for model default (SD1.5=75, SDXL=150, Flux=225)</span>
       </div>
       ```

    5. **Update save handler**: The `onSave(local)` call already sends the full local state. Since `caption_mode` and `max_tokens` are now in the interface and local state, they will be included in the PUT body automatically.

    6. **Update CaptionPage.tsx generate request**:
       - Find the fetch call to `/api/v1/captions/generate`.
       - Replace `style: 'auto'` (or whatever the current value is) with `caption_mode: config.caption_mode` (where `config` is the loaded CaptionProviderConfig).
       - Remove any `style` field from the request body.
       - The `provider_preset: config.provider` line stays unchanged.

    7. **Add over-budget warning in CaptionPage.tsx**:
       - After loading the config (which now has `max_tokens`), determine the effective token budget. If `config.max_tokens` is set, use it.        - For each image in the gallery/thumbnail strip that has a caption, compute approximate token count: `Math.ceil(caption.split(' ').length / 0.75)`.
       - If the approximate count exceeds the token budget, show a warning indicator. Implementation options:
         a. A small orange/yellow badge on the thumbnail in the strip.
         b. An "(over budget)" text next to the caption in the panel.
       - Add a CSS class `caption-over-budget` for the warning indicator styling (orange text or badge).

    8. **CSS additions** in `App.css`:

       ```css
       }
       ```
