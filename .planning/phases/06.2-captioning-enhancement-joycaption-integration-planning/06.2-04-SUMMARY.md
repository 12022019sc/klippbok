# Phase 06.2 Plan 04: Fix apply_vlm_pipeline Step Order Summary

**Reordered VLM pipeline to strip preamble artifacts before anchor injection so ^-anchored regex matches raw VLM output at position 0, preventing preambles like "Here is a caption:" from surviving post-processing when anchor_word is set**

## Accomplishments

- Identified root cause: `_prepend_anchor` ran first, shifting preamble text away from position 0, causing `^`-anchored regex in `_strip_vlm_artifacts` to miss it
- Fixed step order: artifact stripping now runs before trigger injection on raw VLM output

## Decisions Made

- `06.2-04 PIPELINE-01`: `_strip_vlm_artifacts` must run BEFORE `_prepend_anchor`. The `^`-anchored regex patterns in `_VLM_PREFIX_PATTERNS` only match at position 0. When anchor injection runs first, the preamble is no longer at position 0 (e.g., "Here is a caption: a girl" becomes "Luna, here is a caption: a girl"), so the regex cannot match and the preamble survives. Correct order: strip on raw output, then inject anchor.
