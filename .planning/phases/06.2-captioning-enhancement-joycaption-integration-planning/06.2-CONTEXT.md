# Phase 06.2: Captioning Enhancement — JoyCaption Integration Planning - Context

**Gathered:** 2026-03-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Enhance the captioning system with JoyCaption-inspired caption modes (applied universally across all providers), context-only modes for character LoRA training, provider-specific post-processing pipelines, model-aware token budgets, and trigger word injection. The `use_case` concept is removed — caption modes are the single axis for controlling output style.

</domain>

<decisions>
## Implementation Decisions

### Caption modes
- **5 universal modes** available across all providers (JoyCaption uses natively; VLMs get prompt-engineered equivalents):
  1. **Booru Tags** — comma-separated tags (SD1.5 LoRA)
  2. **Context Only (Tags)** — tags excluding physical appearance (Character LoRA)
  3. **Context Only (Natural)** — NL excluding physical appearance (Character LoRA)
  4. **Descriptive** — detailed natural language (SDXL/Flux)
  5. **Straightforward** — factual NL, no speculation (SDXL/Flux)
- Dropped from JoyCaption's full set: "Booru Tags (Short)" (use token budget instead) and "Danbooru" (niche anime syntax, merge into Booru Tags)
- **Default mode: Context Only (Tags)** — primary use case is SD1.5 character LoRAs
- Mode selector is a **dropdown in the collapsible config section** on CaptionPage (next to provider dropdown)
- When Tags/Booru mode is selected with a VLM provider, the VLM is prompted to output comma-separated booru-style tags (not routed to WD Tagger)

### use_case removal
- `use_case` (character/style/motion/object) is **removed entirely** — not just hidden, fully dropped
- The 5 caption modes replace use_case completely
- Context Only modes handle what character use_case did
- Other modes are use_case-agnostic (full captions)
- `prompts.py` templates rewritten around modes, not use_case

### Context-only filtering
- Context Only modes auto-filter appearance-related tags (hair color, eye color, clothing, body type)
- **Curated default tag blacklist + user-editable list** — defaults ship with a researched appearance tag set, user can add/remove via global config
- Character LoRAs only for now — style/object LoRA filtering deferred
- For NL context-only: VLM prompt instructs to exclude physical appearance description

### Post-processing pipelines
- **Provider-specific pipelines** (not unified):
  - **VLM providers** (LM Studio, NanoGPT, Gemini): trigger word injection → max token trimming → artifact stripping (remove "Here is a caption:", markdown formatting, quotes)
  - **JoyCaption**: existing cleanup (strip prefixes, blacklist, dedup) + add context-only appearance filter + token budget trimming
- **Tag blacklist** (removing "watermark", "signature", etc.) runs in **tag-mode output only** — NL captions are not tag-filtered
- Trigger word is **never trimmed** by token budget

### Token budgets
- **Model-aware defaults** from active model profile, with user override:
  - SD1.5: ~75 tokens (CLIP L/14 limit)
  - SDXL: ~150 tokens (dual CLIP)
  - Flux: ~225 tokens (T5-XXL)
- User can override via a max-tokens field in the config section
- **Smart trimming** when over budget:
  - NL captions: trim at last complete sentence within budget
  - Tags: drop lowest-priority tags from the end (highest confidence tags first)
- **Over-budget warning** shown in CaptionPage UI per-image (no continuous token counter — just a warning indicator when exceeded)

### Trigger word injection
- **Keep prepend behavior** — trigger word always appears first in caption
- Current `_prepend_anchor()` logic preserved but formalized as part of provider pipeline
- Trigger word is protected from token budget trimming

### Claude's Discretion
- Exact prompt templates for each mode × provider combination
- Appearance tag blacklist curation (specific booru tag categories to filter)
- VLM artifact stripping patterns (regex or string matching)
- Token counting implementation (approximate word-based or tokenizer-based)
- Smart sentence-boundary trimming algorithm
- Tag confidence ordering for VLM-generated tags
- Config section UI layout for mode dropdown and max-tokens field

</decisions>

<specifics>
## Specific Ideas

- JoyCaption's actual mode set was the reference (screenshot provided by user) — 7 modes narrowed to 5 practical ones
- Primary use case is SD1.5 character LoRAs — Context Only (Tags) as default reflects this
- "Booru Tags (Short)" dropped because token budgets achieve the same conciseness control
- "Danbooru" (strict anime syntax) merged into Booru Tags — not distinct enough to justify a separate mode

<code_context>
## Existing Code Insights

### Reusable Assets
- `CaptionConfig` (caption/models.py): Has provider, anchor_word, custom_prompt fields — needs `caption_mode` field added, `use_case` removed
- `prompts.py`: Has `_fill_prompt()` with anchor injection and use_case templates — rewrite templates around 5 modes
- `captioner.py`: Has `_prepend_anchor()` — formalize as pipeline step
- `joycaption.py`: Has inline tag cleanup (blacklist, dedup, strip prefixes) — extend with context-only filter + token trim
- `caption_service.py`: Routes by style (booru vs NL) — extend to route by caption_mode
- `openai_compat.py`, `gemini.py`: VLM backends — add mode-aware prompt selection
- `CaptionGenerateRequest` (api/models.py): Has `style` field — replace with `caption_mode`
- `ProviderConfigSection.tsx`: Provider config UI — add mode dropdown and max-tokens field
- `ModelProfile` (config/model_profiles.py): Has caption_style field — add token budget default

### Established Patterns
- Provider-specific routing in caption_service.py (booru → WD Tagger, NL → VLM backend)
- JoyCaption subprocess integration with `--trigger` arg and inline Python script
- Global config (~/.klippbok/config.json) for cross-project settings
- Per-project manifest for project-specific settings (anchor_word)

### Integration Points
- `CaptionConfig.use_case` → remove field, migrate to `caption_mode`
- `CaptionGenerateRequest.style` → replace with `caption_mode` enum
- `caption_service.caption_image_for_project()` → route by caption_mode instead of style
- `prompts.py` templates → rewrite around 5 modes
- `ModelProfile` → add `default_token_budget` field
- `ProviderConfigSection.tsx` → add mode dropdown, max-tokens field
- `CaptionPage.tsx` → show over-budget warning per image

</code_context>
