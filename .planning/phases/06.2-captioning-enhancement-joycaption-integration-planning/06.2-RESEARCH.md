## Summary

Phase 06.2 replaces the `use_case` axis with a 5-mode `caption_mode` axis that unifies how all providers generate captions. The core work is: (1) rewrite `prompts.py` with mode-keyed templates for both images and videos, (2) replace `CaptionConfig.use_case` + `CaptionGenerateRequest.style` with `caption_mode`, (3) add provider-specific post-processing pipelines with token budget trimming and artifact stripping, (4) implement appearance tag filtering for Context Only modes, (5) add `default_token_budget` to `ModelProfile`, and (6) extend `ProviderConfigSection.tsx` with a mode dropdown and max-tokens field plus a per-image over-budget warning in `CaptionPage.tsx`.

The JoyCaption inline runner script (`_JOYCAPTION_RUNNER_SCRIPT` in `joycaption.py`) currently uses a hardcoded `"Write a list of Booru-like tags for this image."` prompt with no mode awareness. This must be parameterized to accept a `--mode` argument and route to the appropriate prompt. The runner also needs the appearance-tag filter integrated into its cleanup pass.

The existing codebase is well-positioned for this change. `caption_service.py` already routes by style — extending it to route by `caption_mode` is a clean substitution. `CaptionConfig` is frozen Pydantic, so adding `caption_mode` and removing `use_case` produces a clean model boundary. The most complex new logic is the token budget trimming and the appearance tag blacklist, which are independent pure functions and testable in isolation.

**Primary recommendation:** Implement as 4 waves — (1) backend models + prompts rewrite, (2) post-processing pipelines (token budget + appearance filter + artifact stripping), (3) JoyCaption runner mode parameterization, (4) frontend UI extension.

### Token Counting: Approximate Word-Based (Claude's Discretion Decision)

**Decision rationale:** tiktoken is an OpenAI dependency not in the project. Installing it for approximate counting is over-engineering. For SD1.5 (75-token budget), SDXL (150), Flux (225), a word-count approximation is sufficient:

```python
# Approximate: 1 token ≈ 0.75 words (OpenAI rule of thumb)
# Or simpler: count comma-separated tags for tag modes
def _count_tokens_approx(text: str) -> int:
    """Approximate token count. 1 token ≈ 0.75 words."""
    words = text.split()
    return max(1, round(len(words) / 0.75))
```

For tag mode, count tags directly (each tag ≈ 1-3 tokens):

```python
def _count_tags(caption: str) -> int:
    """Count comma-separated tags."""
    return len([t for t in caption.split(",") if t.strip()])
```

**Installation:** No new packages needed.

```python
# klippbok/caption/pipeline.py

def apply_vlm_pipeline(
    caption: str,
    anchor_word: str | None,
    token_budget: int,
    caption_mode: str,
) -> str:
    """VLM providers: trigger → trim → artifact strip."""
    # 1. Trigger word injection (always first)
    if anchor_word:
        caption = _prepend_anchor(caption, anchor_word)
    # 2. Artifact stripping (before trimming — removes extra text first)
    caption = _strip_vlm_artifacts(caption)
    # 3. Token budget trimming (trigger word protected)
    caption = _trim_to_budget(caption, token_budget, anchor_word, caption_mode)
    return caption


def apply_joycaption_pipeline(
    caption: str,
    anchor_word: str | None,
    token_budget: int,
    caption_mode: str,
    appearance_blacklist: list[str],
) -> str:
    """JoyCaption: strip prefixes → blacklist → dedup → context filter → trim."""
    caption = _strip_joycaption_prefixes(caption)
    caption = _apply_tag_blacklist(caption, _NOISE_TAG_BLACKLIST)
    caption = _dedup_tags(caption)
    if caption_mode in ("context_only_tags", "context_only_natural"):
        caption = _filter_appearance_tags(caption, appearance_blacklist)
    if anchor_word:
        caption = _prepend_anchor(caption, anchor_word)
    caption = _trim_to_budget(caption, token_budget, anchor_word, caption_mode)
    return caption
```

### VLM Artifact Stripping

```python
import re

_VLM_PREFIX_PATTERNS = [
    r"^here is a (?:caption|description)[:\s]+",
    r"^here are (?:some )?(?:booru[-\s]?like )?tags[:\s]+",
    r"^(?:caption|tags)[:\s]+",
    r"^(?:sure|certainly|of course)[!,.]?\s+",
    r'^"(.+)"$',           # Wrapping quotes
]

def _strip_vlm_artifacts(text: str) -> str:
    """Remove common VLM response preambles and formatting."""
    text = text.strip()
    # Strip markdown bold/italic
    text = re.sub(r'\*{1,2}([^*]+)\*{1,2}', r'\1', text)
    # Strip wrapping quotes
    if text.startswith('"') and text.endswith('"'):
        text = text[1:-1]
    # Strip preamble prefixes (case-insensitive)
    for pattern in _VLM_PREFIX_PATTERNS:
        text = re.sub(pattern, '', text, flags=re.IGNORECASE)
    return text.strip()
```

### Token Budget Trimming

```python
def _trim_to_budget(
    caption: str,
    token_budget: int,
    anchor_word: str | None,
    caption_mode: str,
) -> str:
    """Trim caption to token budget. Trigger word is never trimmed."""
    if _count_tokens_approx(caption) <= token_budget:
        return caption

    is_tag_mode = caption_mode in ("booru_tags", "context_only_tags")

    if is_tag_mode:
        # Tags: drop from end (lowest-confidence tags last)
        tags = [t.strip() for t in caption.split(",") if t.strip()]
        # Protect anchor word (always first)
        anchor_tag = anchor_word.lower() if anchor_word else None
        protected = []
        rest = []
        for tag in tags:
            if anchor_tag and tag.lower() == anchor_tag:
                protected.append(tag)
            else:
                rest.append(tag)
        # Drop from end until under budget
        while rest and _count_tokens_approx(", ".join(protected + rest)) > token_budget:
            rest.pop()
        return ", ".join(protected + rest)
    else:
        # NL captions: trim at last complete sentence within budget
        sentences = re.split(r'(?<=[.!?])\s+', caption)
        result = []
        for sentence in sentences:
            candidate = " ".join(result + [sentence])
            if _count_tokens_approx(candidate) <= token_budget:
                result.append(sentence)
            else:
                break
        return " ".join(result) if result else caption[:token_budget * 4]  # fallback
```

### Anti-Patterns to Avoid

- **Unified pipeline for all providers:** JoyCaption's subprocess output is already tag-split; applying VLM artifact stripping to it would corrupt valid tags. Keep pipelines separate.
- **Routing booru_tags to WD Tagger when a VLM is configured:** When user explicitly sets a VLM provider and selects `booru_tags`, they want VLM-generated booru-style tags, not WD Tagger output. The WD Tagger path is only for when no VLM is configured/active.
- **Removing `_prepend_anchor()` from captioner.py:** The CLI path (`caption_clips`) still uses it. Move to `pipeline.py` and import from there, but keep the function accessible.
- **Storing appearance_blacklist_extra in per-project manifest:** Appearance filtering preference is global, not per-project. Store additions in `~/.klippbok/config.json`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Sentence boundary splitting | Custom regex splitter | `re.split(r'(?<=[.!?])\s+', text)` | Python stdlib regex handles most prose well; covers `.`, `!`, `?` terminators |
| Tokenizer for budget | tiktoken integration | Word-count approximation (`len(words) / 0.75`) | tiktoken adds ~10MB dependency for a rough count; word approximation is within 10% and sufficient |
| Tag deduplication | Set-based dedup with order preservation | Existing `joycaption.py` dedup pattern (`seen = set(); unique_tags = []`) | Already implemented and correct in joycaption.py; reuse as shared utility |
| Config merging | Deep merge logic | Flat field override: `manifest.get("max_tokens") or profile.default_token_budget` | Config is shallow; flat fallback chain is simpler and already the project pattern |

## Common Pitfalls

### Pitfall 1: `CaptionConfig` is Frozen — Evolution Strategy

**What goes wrong:** `CaptionConfig(frozen=True)` means you cannot mutate instances. If you add `caption_mode` and remove `use_case`, any existing code creating `CaptionConfig(use_case=...)` will raise a validation error.

**Why it happens:** Pydantic v2 frozen models raise `ValidationError` for unknown fields by default.

**How to avoid:** Check `model_config` — it has no `extra = "ignore"` setting. Either add `model_config = ConfigDict(frozen=True, extra="ignore")` temporarily during migration, or do a single-pass search-and-replace of all `CaptionConfig(use_case=...)` callsites before removing the field.

**Warning signs:** `ValidationError: Extra inputs are not permitted` in tests when `use_case` is passed.

### Pitfall 2: `build_vlm_config_from_global()` Doesn't Pass `caption_mode`

**What goes wrong:** `build_vlm_config_from_global()` in `caption_service.py` constructs `CaptionConfig` from the global config dict. If it doesn't extract `caption_mode` from the global config and pass it, all VLM captions will use the default mode regardless of the user's selection.

**Why it happens:** The function was written for the old `use_case`/`style` system. Easy to miss when updating.

**How to avoid:** Update `build_vlm_config_from_global()` to extract `caption_mode` and `max_tokens` from `global_config` and pass them to `CaptionConfig(...)`.

### Pitfall 3: JoyCaption Subprocess Script Is Inline Python — Must Be Updated Carefully

**What goes wrong:** `_JOYCAPTION_RUNNER_SCRIPT` is a multi-line string of Python code embedded in `joycaption.py`. Syntax errors inside it are not caught at import time — they only fail at runtime when JoyCaption is actually invoked.

**Why it happens:** The script is written to a temp file and executed by a different Python interpreter (JoyCaption's venv). No static analysis applies.

**How to avoid:** After editing the runner script, add a dedicated unit test that writes the script to a temp file and runs `python -c "compile(open(path).read(), path, 'exec')"` to syntax-check it without executing it.

**Warning signs:** JoyCaption subprocess fails immediately with `SyntaxError` in the first SSE event.

### Pitfall 4: `style` Field in `CaptionGenerateRequest` Has Callers in the Frontend

**What goes wrong:** `CaptionGenerateRequest.style` is sent from the frontend in `CaptionPage.tsx` via `POST /captions/generate`. If you rename it to `caption_mode` on the backend without updating the frontend type and the POST body, the field silently becomes `None` (Pydantic ignores unknown fields).

**Why it happens:** TypeScript interface in `CaptionPage.tsx` has a `style` field in the request body. Frontend/backend are decoupled — Pydantic won't warn about missing fields.

**How to avoid:** Update `CaptionPage.tsx` fetch call and local state simultaneously with the backend model change. Search for `style:` in the frontend fetch body.

**Warning signs:** `caption_mode` resolves to `None`/default in every request even when user selected a different mode.

### Pitfall 5: WD Tagger Path Still Valid for `booru_tags` Mode

**What goes wrong:** With `use_case` gone, the old routing was `style == "booru"` → WD Tagger. The new routing must preserve this: when provider is not set or is WD Tagger-compatible, `booru_tags` should still route to `tag_image_booru`. If this is lost, booru tagging for SD1.5 breaks entirely.

**Why it happens:** The `caption_mode` refactor might naively route all modes through VLMs.

**How to avoid:** The WD Tagger path should be: `caption_mode == "booru_tags" AND provider_preset not set (or explicitly "wd_tagger")`. When a VLM provider is active, even `booru_tags` goes through the VLM with a booru-style prompt.

### Pitfall 6: Appearance Tag Blacklist Partial Matching

**What goes wrong:** Filtering tags with `tag in blacklist` misses multi-word tags. For example, `"long blonde hair"` won't match `"blonde hair"` with an exact-match check.

**Why it happens:** Booru tags use underscores (`blonde_hair`) but the WD Tagger output and VLM outputs may use spaces. Also, substring vs. exact matching.

**How to avoid:** Normalize both the candidate tag and the blacklist to lowercase + underscore-replaced with spaces (or vice versa). Use `any(bl in tag_normalized for bl in blacklist_normalized)` for substring matching, not exact matching.

```python
def _normalize_tag(tag: str) -> str:
    return tag.lower().replace("_", " ").strip()

def _tag_is_appearance(tag: str, blacklist: list[str]) -> bool:
    norm = _normalize_tag(tag)
    return any(_normalize_tag(bl) in norm or norm in _normalize_tag(bl) for bl in blacklist)
```

### Pattern: Token Budget Resolution

```python
def _resolve_token_budget(vlm_config: CaptionConfig, manifest: dict) -> int:
    """Resolve effective token budget: vlm_config override > manifest override > profile default."""
    if vlm_config.max_tokens is not None:
        return vlm_config.max_tokens
    manifest_override = manifest.get("max_tokens")
    if manifest_override:
        return int(manifest_override)
    # Fall back to model profile default
    from klippbok.config.model_config import get_profile
    active_profile = manifest.get("active_profile", "sdxl")
    try:
        profile = get_profile(active_profile)
        return profile.default_token_budget
    except Exception:
        return 150  # safe default (SDXL)
```

## Open Questions

1. **WD Tagger mode for Context Only (Tags)**
   - What we know: WD Tagger outputs physical appearance tags (hair color, body type, clothing) which conflict with Context Only mode
   - What's unclear: Should `context_only_tags` mode with WD Tagger route to WD Tagger then apply appearance filter, or route to VLM for VLM-generated context-only tags?
   - Recommendation: Route to WD Tagger + apply appearance filter (simplest path, no VLM needed for character LoRA workflows). Add a post-processing step to `caption_image_for_project` for this case.

2. **`get_caption_style_for_project()` replacement**
   - What we know: `get_caption_style_for_project()` currently returns "booru" or "natural_language" and is called from the API to determine routing
   - What's unclear: Whether to replace it with `get_caption_mode_for_project()` or fold the logic into the routing in `caption_image_for_project()`
   - Recommendation: Replace with `get_caption_mode_for_project()` that reads `caption_mode` from the global config (not the manifest — mode is a global preference, not per-project).

3. **`caption_style_override` in manifest**
   - What we know: Manifest has a `caption_style_override` field (used by `get_caption_style_for_project`)
   - What's unclear: Should this be migrated to `caption_mode_override` or removed entirely?
   - Recommendation: Remove `caption_style_override` from manifest reads. Mode is a global config concern, not per-project. Add migration note to not break existing manifests that have the key (just ignore it).
