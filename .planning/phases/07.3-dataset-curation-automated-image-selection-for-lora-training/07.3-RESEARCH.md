# Phase 7.3: Dataset Curation -- Automated Image Selection for LoRA Training - Research

**Researched:** 2026-03-08
**Domain:** ML-powered image scoring, submodular diversity selection, GPU inference pipeline
**Confidence:** HIGH

## Summary

This phase implements a two-stage curation pipeline: (1) score every gallery image on 7 ML signals, filter by quality floor, then (2) select a maximally diverse subset using submodular optimization (apricot FacilityLocation). Two modes serve different workflows: Character mode anchors on face identity similarity, Style mode emphasizes aesthetics. The frontend follows the established three-state page pattern (Config -> Progress -> Results) with click-to-pin/exclude adjustment and re-diversification.

The project already has 5 of 7 scoring signals implemented as singletons (InsightFace, CLIP, OpenCV Laplacian, MediaPipe Pose, pHash). Three new dependencies are needed: pyiqa (TOPIQ-NR perceptual quality), aesthetic-predictor-v2-5 (SigLIP aesthetic scoring), and apricot-select (Facility Location subset selection). All three are available on PyPI, GPU-compatible, and well-maintained.

**Primary recommendation:** Build `klippbok/curation/` module with scorer.py, diversity.py, pipeline.py, presets.py, models.py following existing service patterns. Reuse all existing ML singletons. Use precomputed cosine similarity matrix for apricot to avoid negative similarity issues.

### Pattern 1: GPU Model Singleton with Lazy Loading
**What:** Each ML model loaded once at first use, cached module-level.
**When to use:** All GPU models (pyiqa, aesthetic predictor, InsightFace, CLIP).
**Example:**
```python
# Source: existing pattern in face_service.py, triage_service.py
_pyiqa_model = None

def _get_pyiqa_model():
    global _pyiqa_model
    if _pyiqa_model is None:
        import pyiqa
        import torch
        device = "cuda" if torch.cuda.is_available() else "cpu"
        _pyiqa_model = pyiqa.create_metric('topiq_nr', device=device)
    return _pyiqa_model
```

### Pattern 3: Precomputed Cosine Similarity for Apricot
**What:** Compute cosine similarity matrix before passing to FacilityLocationSelection.
**When to use:** Diversity selection step -- apricot requires non-negative similarities.
**Example:**
```python
# Source: apricot docs + sklearn
from sklearn.metrics.pairwise import cosine_similarity
from apricot import FacilityLocationSelection

# features: numpy array (N, D) -- concatenated CLIP+Pose+Face embeddings
sim_matrix = cosine_similarity(features)
# cosine_similarity returns values in [-1, 1] but normalized embeddings give [0, 1]
sim_matrix = np.clip(sim_matrix, 0, None)  # safety clamp

selector = FacilityLocationSelection(
    n_samples=target_count,
    metric='precomputed',
    optimizer='lazy',
    verbose=False,
)
selector.fit(sim_matrix)
selected_indices = selector.ranking
```

### Pattern 4: Score Normalization
**What:** Map raw signal scores to 0-1 range for weighted composite.
**When to use:** Combining scores from different domains (face confidence, aesthetic, quality).
**Example:**
```python
def normalize_score(value: float, low: float, high: float) -> float:
    """Linearly normalize a value from [low, high] to [0, 1]."""
    if high <= low:
        return 0.5
    return max(0.0, min(1.0, (value - low) / (high - low)))

# Known ranges per signal:
# InsightFace det_score: [0, 1] -- already normalized
# pyiqa TOPIQ-NR: approximately [0, 1] for natural images
# Aesthetic V2.5: [1, 10] -- normalize with low=3, high=8 (practical range)
# Laplacian variance: [0, ~5000] -- normalize with low=50, high=1000
# Identity similarity: [0, 1] -- cosine similarity, already normalized
```

### Anti-Patterns to Avoid
- **Loading ML models per-request:** Every GPU model must use module-level singleton. Loading pyiqa or aesthetic predictor takes 2-5 seconds.
- **Sequential GPU inference:** Score all images with one model before moving to the next. Do NOT interleave models per-image.
- **Using apricot with raw distance metric on embeddings:** Always precompute cosine similarity matrix. Using `metric='cosine'` converts to distance internally and may produce negative values after max-distance transformation.
- **Storing numpy arrays in Pydantic models:** Convert to `list[float]` for serialization. Keep numpy in memory only during pipeline execution.
- **Re-scoring on re-diversify:** Pin/exclude only affects Phase 2 (diversity selection). Phase 1 scores are cached and reused.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Perceptual quality scoring | Custom blur/noise detector | pyiqa TOPIQ-NR | Trained on large IQA datasets, correlates with human judgment, GPU-accelerated |
| Aesthetic scoring | CLIP-based aesthetic heuristic | aesthetic-predictor-v2-5 | SigLIP-based, works on photos AND illustrations, 1-10 scale |
| Diverse subset selection | Custom greedy selection loop | apricot FacilityLocationSelection | Submodular optimization with theoretical guarantees, handles 1000+ items efficiently |
| Face clustering | Custom distance-threshold grouping | sklearn DBSCAN (already used) | Handles noise points, cosine metric support, proven in face_service.py |
| Cosine similarity matrix | Manual dot product loops | sklearn cosine_similarity | Optimized C implementation, handles batches, returns proper matrix |

**Key insight:** The scoring signals are the easy part (just call model inference). The hard part is combining them intelligently (normalization + weighting) and selecting a diverse subset (submodular optimization). Apricot solves the latter with mathematical guarantees that no hand-rolled greedy approach can match.

## Common Pitfalls

### Pitfall 1: Apricot Negative Similarity Values
**What goes wrong:** FacilityLocationSelection silently produces wrong results with negative similarities.
**Why it happens:** Cosine distance (1 - cosine_similarity) used internally by apricot when metric='cosine'. The max-distance transformation can produce negative values.
**How to avoid:** Always precompute the similarity matrix with sklearn's cosine_similarity and pass metric='precomputed'. Clamp to non-negative.
**Warning signs:** Selected subset clusters in one corner of embedding space instead of spreading.

### Pitfall 2: VRAM Exhaustion from Model Stacking
**What goes wrong:** Loading pyiqa + aesthetic + InsightFace + CLIP simultaneously exceeds VRAM.
**Why it happens:** Each model stays in VRAM as a singleton. Total ~1.25GB but spikes during inference.
**How to avoid:** RTX 5080 has 16GB -- 1.25GB total is safe. But if future models are added, consider sequential load/unload. Monitor with torch.cuda.memory_allocated().
**Warning signs:** CUDA out of memory during batch scoring.

### Pitfall 3: MediaPipe Pose Returning None for Non-Person Images
**What goes wrong:** MediaPipe PoseLandmarker returns empty results for images without a visible full/partial body.
**Why it happens:** Style mode images may not contain people at all.
**How to avoid:** Treat pose_vector as optional. Use zero vector for images without detected pose. In diversity concatenation, zero-pad missing pose vectors.
**Warning signs:** NaN in concatenated feature matrix crashes apricot.

### Pitfall 4: pHash Comparison Scale
**What goes wrong:** `compute_phash` returns a hex string, not a similarity score.
**Why it happens:** pHash is used for dedup (binary is_duplicate flag), not scoring.
**How to avoid:** Use `are_near_duplicates()` from image_service.py for the boolean flag. Don't try to incorporate pHash into the composite score -- it's a filter, not a signal.
**Warning signs:** Trying to normalize a Hamming distance into the 0-1 composite.

### Pitfall 5: Aesthetic Predictor V2.5 Requires bfloat16
**What goes wrong:** Model inference fails or produces wrong scores on older GPUs without bfloat16.
**Why it happens:** The reference code uses `torch.bfloat16` which requires Ampere+ GPUs.
**How to avoid:** RTX 5080 (Blackwell) supports bfloat16. But add fallback to float16 for compatibility.
**Warning signs:** RuntimeError about unsupported dtype.

### Pitfall 6: InsightFace Face Area Ratio Calculation
**What goes wrong:** Bbox coordinates from InsightFace are absolute pixels, need image dimensions for ratio.
**Why it happens:** InsightFace returns `face.bbox` as [x1, y1, x2, y2] in pixel coordinates.
**How to avoid:** Calculate area ratio as `(x2-x1)*(y2-y1) / (img_width*img_height)`.
**Warning signs:** All face_area_ratio values are >> 1.0 or tiny fractions that don't make sense.

```python
# Source: https://github.com/discus0434/aesthetic-predictor-v2-5
import torch
from aesthetic_predictor_v2_5 import convert_v2_5_from_siglip
from PIL import Image

model, preprocessor = convert_v2_5_from_siglip(
    low_cpu_mem_usage=True,
    trust_remote_code=True,
)
model = model.to(torch.bfloat16).cuda().eval()

image = Image.open("image.jpg").convert("RGB")

    preprocessor(images=image, return_tensors="pt")
    .pixel_values.to(torch.bfloat16).cuda()

    score = model(pixel_values).logits.squeeze().float().cpu().numpy()
# score is float, typically 1.0-10.0; 5.5+ is "great"
```

### MediaPipe Pose Vector Extraction
```python
# Source: existing pattern from klippbok/video/extract.py
import mediapipe as mp
import numpy as np
from mediapipe.tasks.python import vision

# Get 33 landmarks -> compute ~20 joint angles
# Key angles: shoulder, elbow, hip, knee at each side + spine angles
def compute_pose_vector(landmarks) -> list[float]:
    """Extract ~20-D angle vector from 33 3D landmarks."""
    angles = []
    # Define angle triplets (joint, start, end)
    ANGLE_TRIPLETS = [
        (11, 13, 15),  # left elbow
        (12, 14, 16),  # right elbow
        (13, 11, 23),  # left shoulder
        (14, 12, 24),  # right shoulder
        (23, 25, 27),  # left knee
        (24, 26, 28),  # right knee
        (11, 23, 25),  # left hip
        (12, 24, 26),  # right hip
        # ... more angles for spine, neck
    ]
    for a, b, c in ANGLE_TRIPLETS:
        angle = compute_angle(landmarks[a], landmarks[b], landmarks[c])
        angles.append(angle / 180.0)  # normalize to 0-1
    return angles
```

## Open Questions

1. **Aesthetic Predictor V2.5 batch inference**
   - What we know: The example shows single-image inference. The model accepts batched pixel_values tensors.
   - What's unclear: Whether the preprocessor handles batch input cleanly or needs manual stacking.
   - Recommendation: Test batch preprocessing in implementation. If it fails, use a simple for-loop with single-image preprocessing and stack tensors manually.

2. **pyiqa TOPIQ-NR output range**
   - What we know: The metric is described as outputting quality scores. Documentation says it's a no-reference metric.
   - What's unclear: The exact output range for natural photos (claimed ~0-1 but may vary).
   - Recommendation: Run calibration on a few sample images during implementation. Use min-max normalization from observed range rather than assuming [0, 1].

3. **Apricot performance at scale**
   - What we know: FacilityLocationSelection works on precomputed similarity matrices. 400 images = 400x400 matrix.
   - What's unclear: Performance with 1000+ images (1M element matrix).
   - Recommendation: 400x400 is trivial (<1s). For 1000+, the lazy optimizer is O(N*K) where K=target_count, still fast. No concern for expected dataset sizes.
