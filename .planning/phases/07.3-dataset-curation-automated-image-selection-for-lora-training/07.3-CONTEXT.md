# Phase 07.3: Dataset Curation — Automated Image Selection for LoRA Training - Context

**Gathered:** 2026-03-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Automated image curation pipeline that scores all gallery images on multiple ML quality/diversity dimensions, then selects a maximally diverse subset for LoRA training. Two modes: Character (identity-anchored with face embedding similarity) and Style (aesthetic-focused). Users review curated results, adjust via click-to-pin/exclude, and apply the selection to the gallery for downstream Crop/Caption workflow. Non-destructive — rejected images stay in gallery, just unselected.

</domain>

<decisions>
## Implementation Decisions

### Review & adjustment UX
- **Two-panel layout**: Selected images in a top grid with composite score badges, rejected pool in a collapsible bottom section with dimmed/smaller thumbnails
- **Click actions for adjustment**: Click a selected image to exclude it (moves to rejected). Click a rejected image to pin it (moves to selected). No drag-and-drop or explicit button overlays
- **Score breakdown**: Popover with horizontal bar chart on click/hover showing each scoring dimension (face, sharpness, aesthetic, quality, identity) with composite score at top
- **Re-diversify button**: After pin/exclude adjustments, re-runs Phase 2 diversity selection respecting pins & exclusions
- **Pipeline summary**: Funnel stats (scanned → passed quality → selected) plus diversity metrics (pose variety, background variety, expression spread) displayed at top of results

### Workflow integration
- **Entry points**: Both a SelectionToolbar "Curate" button on Gallery AND a NavBar "Curate" link
- **NavBar order**: Gallery > Import > Video > Cleanup > **Curate** > Crop > Caption > Triage > Settings
- **Apply action**: Sets gallery's selectedImageIds to the curated set, turns on selection mode, navigates back to Gallery. From there, user proceeds to Crop or Caption with only curated images. Non-destructive — rejected images remain in gallery
- **Persistence**: Curation results saved to `.klippbok/curation_results.json`. Users can revisit /curate and see their last run without re-scoring. Re-run overwrites previous results

### Scoring signals & weights
- **All 7 signals confirmed**:
  1. InsightFace — face confidence, pose angles, area ratio, face embedding (GPU)
  2. pyiqa TOPIQ-NR — perceptual quality (GPU)
  3. Aesthetic Predictor V2.5 — aesthetic/composition score (GPU)
  4. OpenCV Laplacian — face-region + whole-image sharpness (CPU)
  5. MediaPipe Pose — normalized joint angle vector ~20-D (CPU, already installed from autocrop)
  6. CLIP zero-shot — occlusion flags (GPU)
  7. pHash — duplicate detection (CPU, already implemented in image_service)
- **Character mode weights**: Face 40%, Technical 25%, Aesthetic 20%, Other 15%
- **Style mode weights**: Aesthetic 35%, Technical 30%, Face 20%, Other 15%
- **Diversity selection**: apricot FacilityLocation on concatenated CLIP (512-D) + Pose (20-D) + Face (512-D) embeddings, normalized
- **Quality floor**: Adjustable with 30% default (exposed as slider/input in Advanced settings)

### Configuration & presets
- **Essential config visible**: Mode (Character/Style), Target count, Reference face indicator
- **Advanced settings behind toggle**: Quality floor %, face confidence threshold, pose angle limit, identity threshold, diversity weights
- **Reference face**: Auto-detected from face clustering. Curation auto-runs face clustering as first pipeline step if no clusters exist. Picks largest cluster's primary reference automatically
- **Model-aware target count defaults** (community best practices):
  - SD1.5 → 40 (sweet spot 20-50)
  - SDXL → 80 (sweet spot 50-100)
  - Flux → 100 (sweet spot 80-150)
  - Pony → 70 (sweet spot 40-100)
  - Custom → 60

### Claude's Discretion
- Config panel and results page CSS/layout (consistent with existing pages)
- SSE event naming for curation operations (following existing patterns)
- Score normalization algorithm (how raw signal scores map to 0-1 composite)
- Face clustering integration details (reuse face_service.py vs inline)
- Advanced settings panel layout (accordion, collapsible, or drawer)
- How diversity metrics are computed and displayed in the summary
- Exact popover positioning and bar chart styling

</decisions>

<specifics>
## Specific Ideas

- Primary use case is curating a LoRA training dataset from hundreds of mixed-source images (video frames + standalone photos) after Cleanup has removed irrelevant content
- Pipeline flow: Import → Video → Cleanup → **Curate** → Crop → Caption → Export
- "Apply" should feel seamless — one click returns to Gallery with the curated set selected, ready for Crop/Caption
- The auto-detect reference face from clustering is key — avoids manual face picking UX entirely
- Target count defaults should reflect community best practices, not conservative minimums — users are better served by the right starting point
- Design doc (`docs/plans/2026-03-07-dataset-curation-design.md`) covers full architecture, data models, API endpoints, dependencies, and performance budget (~33s for 400 images on RTX 5080)

</specifics>

<code_context>
## Existing Code Insights

### Reusable Assets
- `klippbok/triage/embeddings.py`: CLIPEmbedder singleton with encode_text/image/images, similarity, best_match_score — core for CLIP embeddings and occlusion detection
- `klippbok/services/face_service.py`: _get_face_app() InsightFace singleton (GPU ctx_id=0), compute_face_embeddings(), cluster_face_embeddings() — face detection, embedding, clustering
- `klippbok/services/triage_service.py`: _get_or_create_embedder() singleton pattern — avoids reloading 600MB CLIP model
- `klippbok/services/cleanup_service.py`: Layered CLIP + InsightFace scoring pattern, compute_confidence(), classify_items() — reference for scoring architecture
- `klippbok/services/image_service.py`: batch_import_images(), compute_phash(), are_near_duplicates() — pHash dedup already implemented
- `klippbok/video/extract.py`: MediaPipe PoseLandmarker — already installed and used for autocrop
- `frontend/src/components/Gallery/SelectionToolbar.tsx`: Has Upscale/Crop/Process Videos buttons + selectByFilter() pattern
- `frontend/src/pages/CleanupPage.tsx`: Three-state page pattern (Setup → Progress → Review) — reference for CuratePage structure
- `frontend/src/stores/appStore.ts`: Zustand store with selectionMode, selectedImageIds, triageResults, cleanupResults patterns

### Established Patterns
- SSE for long-running ops: POST start → GET /events/{op_id} → cancel endpoint (asyncio.Queue + named events)
- Module-level singleton for heavy ML models (_get_or_create_embedder(), _get_face_app())
- run_in_executor for CPU-bound ML work
- SHA256[:16] of relative path as image ID (consistent across all services)
- TanStack Query cache invalidation for data refresh
- Results persistence in .klippbok/ project directory

### Integration Points
- SelectionToolbar.tsx: Add "Curate" button navigating to /curate
- NavBar.tsx: Add "Curate" link after Cleanup
- App.tsx: Add /curate route
- appStore.ts: Add curationResults, pinnedIds, excludedIds state
- .klippbok/curation_results.json: Persisted results file
- ModelProfile system: Load target count defaults from model presets

</code_context>
