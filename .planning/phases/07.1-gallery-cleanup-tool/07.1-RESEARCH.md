# Phase 07.1: Gallery Cleanup Tool - Research

**Researched:** 2026-03-06
**Domain:** ML-powered media classification (CLIP text-to-image + InsightFace), SSE background tasks, file management
**Confidence:** HIGH

## Summary

This phase builds a cleanup tool that scans all imported media in a project, classifies each item by CLIP text-to-image similarity and InsightFace face detection, and presents flagged items for user review before moving them to a `_review/` subfolder. The architecture is well-constrained: all core ML components (CLIPEmbedder, InsightFace face detection), SSE patterns, and file-move patterns already exist in the codebase. The primary new work is (1) a cleanup-specific service that combines CLIP text classification with face detection into a combined score, (2) a new API router with SSE support, (3) a dedicated `/cleanup` frontend page, and (4) manifest + file management for confirmed removals.

The existing triage system uses CLIP image-to-image similarity (comparing against concept reference images). Cleanup uses CLIP text-to-image similarity (comparing against text prompts like "photo of a woman") -- a fundamentally different approach that requires a separate service, separate threshold, and separate scoring logic. The `encode_text()` and `encode_texts()` methods on CLIPEmbedder already support this. CLIP text-to-image scores are naturally lower (~0.20-0.35) than image-to-image scores (~0.60-0.90), which is why a separate threshold is needed.

**Primary recommendation:** Build a `cleanup_service.py` that composes existing `CLIPEmbedder` singleton and `_get_face_app()` singleton, uses the established SSE background task pattern from `triage.py` router, and follows the `organize_clips()` sidecar-aware file move pattern for confirmed removals.

### Pattern 1: Layered CLIP + InsightFace Classification
**What:** Two-pass classification -- CLIP text-to-image first (fast, batch-friendly), InsightFace face detection second (slower, only on CLIP-positive items)
**When to use:** Every item in the cleanup scan
**Example:**
```python
# Step 1: Encode all positive/negative text prompts ONCE (cached)
positive_embeddings = embedder.encode_texts(positive_prompts)
negative_embeddings = embedder.encode_texts(negative_prompts)

# Step 2: For each image, compute CLIP text-to-image similarity
image_embedding = embedder.encode_image(image_path)
pos_score = max(float(np.dot(image_embedding, pe)) for pe in positive_embeddings)
neg_score = max(float(np.dot(image_embedding, ne)) for ne in negative_embeddings)
clip_score = pos_score - neg_score  # net person-relevance

# Step 3: If CLIP score >= threshold, run InsightFace
if clip_score >= clip_threshold:
    faces = face_app.get(cv2_image)
    has_face = len(faces) > 0
else:
    has_face = False  # Skip InsightFace for clearly non-person items
```

### Pattern 4: Sidecar-Aware File Move
**What:** Move files with their sidecar files (.txt, .json, .jsonl) together
**When to use:** Moving flagged items to `_review/`
**Example:** Follows `organize_clips()` pattern from `triage.py`:
```python
sidecar_extensions = {".txt", ".json", ".jsonl"}
shutil.move(str(source), str(dest))
for ext in sidecar_extensions:
    sidecar = source.with_suffix(ext)
    if sidecar.is_file():
        shutil.move(str(sidecar), str(dest.parent / sidecar.name))
```

### Anti-Patterns to Avoid
- **Reloading CLIP model per request:** Use existing `_get_or_create_embedder()` singleton -- never instantiate CLIPEmbedder in the cleanup service
- **Reloading InsightFace per request:** Use existing `_get_face_app()` singleton
- **Running ML in the event loop:** Always use `run_in_executor` for CPU-bound CLIP/InsightFace work
- **Deleting files:** NEVER delete files -- always move to `_review/`
- **Encoding text prompts per image:** Encode all text prompts ONCE at scan start, reuse embeddings for every image

## Common Pitfalls

### Pitfall 1: CLIP Text-to-Image Score Range Mismatch
**What goes wrong:** Using triage threshold (~0.70) for text-to-image similarity
**Why it happens:** CLIP text-to-image scores are fundamentally different from image-to-image scores. Text-to-image typically ranges 0.20-0.35 for good matches.
**How to avoid:** Use a separate `cleanup_threshold` (recommend ~0.25 default). Never share threshold with triage.
**Warning signs:** Everything gets flagged for removal, or nothing gets flagged.

### Pitfall 2: Running InsightFace on Non-Person Images
**What goes wrong:** Loading InsightFace model and running face detection on screenshots, memes, landscapes
**Why it happens:** InsightFace is slow (~0.5s/image on CPU). Running on 1000 non-person images wastes minutes.
**How to avoid:** CLIP text filter runs FIRST. Only items scoring above CLIP threshold get InsightFace pass.
**Warning signs:** Scan takes 10x longer than expected.

### Pitfall 3: Encoding Text Prompts Per Image
**What goes wrong:** Calling `encode_text()` for each prompt for each image
**Why it happens:** Naive implementation encodes prompts inside the per-image loop
**How to avoid:** Encode all positive and negative prompts ONCE before the image loop. Store as numpy arrays.
**Warning signs:** Each image takes 100ms+ for text encoding alone.

### Pitfall 4: Manifest Corruption on Partial Removal
**What goes wrong:** Removing entries from manifest while another operation is reading it
**Why it happens:** No file locking on manifest.json
**How to avoid:** Cleanup removal is a single synchronous operation (not concurrent with import/triage). Load, filter, write atomically.
**Warning signs:** Missing images in gallery after cleanup.

### Pitfall 5: Auto-Start Race Condition
**What goes wrong:** Scan starts before page component is fully mounted, or starts twice
**Why it happens:** React effect fires on mount, but navigation state may not be settled
**How to avoid:** Use a ref (`hasAutoStarted`) to prevent double-start, similar to `hasAutoImported` pattern in GalleryPage.
**Warning signs:** Two cleanup operations running simultaneously.

### Pitfall 6: Forgetting to Move Sidecar Files
**What goes wrong:** Image moved to `_review/` but its `.txt` caption file stays behind
**Why it happens:** Only moving the primary file, forgetting sidecars
**How to avoid:** Use the sidecar extension set pattern from `organize_clips()`
**Warning signs:** Orphaned `.txt` files in project directory.

### Score Combination Algorithm (Discretion Area)
```python
# Recommended approach: weighted combination
def compute_confidence(clip_score: float, has_face: bool, clip_threshold: float) -> float:
    """Combine CLIP text similarity and face detection into a 0-1 confidence score.

    - CLIP score is normalized relative to threshold (maps ~0.15-0.40 to 0-1 range)
    - Face detection is a binary boost (+0.3 if face found)
    - Clamped to 0.0-1.0
    """
    # Normalize CLIP score: threshold maps to ~0.5
    normalized_clip = min(1.0, max(0.0, (clip_score - 0.10) / 0.30))
    face_boost = 0.3 if has_face else 0.0
    return min(1.0, normalized_clip * 0.7 + face_boost)

def classify(confidence: float) -> Literal["keep", "review", "remove"]:
    if confidence >= 0.6:
        return "keep"
    elif confidence >= 0.3:
        return "review"  # shown to user for manual decision
    else:
        return "remove"
```

## Open Questions

1. **Optimal CLIP text-to-image threshold default**
   - What we know: Text-to-image scores typically 0.20-0.35 for good matches. Triage uses 0.70 for image-to-image.
   - What's unclear: Exact default that balances false positives vs false negatives for Instagram/social media content
   - Recommendation: Default 0.25, expose as slider in UI (0.15-0.40 range). The UI review step catches false positives.

2. **InsightFace batching strategy**
   - What we know: InsightFace processes one image at a time via cv2 (no native batching). Each face detection takes ~0.3-0.5s on CPU.
   - What's unclear: Whether to batch or process one-by-one
   - Recommendation: Process one-by-one with progress callback (simpler, allows cancellation between items, matches existing `compute_face_embeddings` pattern)

3. **Auto-start mechanism when redirected from Gallery**
   - What we know: GalleryPage has a "Cleanup" button that navigates to `/cleanup`. Need auto-start behavior.
   - What's unclear: How to signal "auto-start" vs "manual visit"
   - Recommendation: Use URL search param `?autostart=true` or appStore flag set by Gallery before navigation. Check on mount, start if true, clear flag.
