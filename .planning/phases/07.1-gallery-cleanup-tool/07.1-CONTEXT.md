# Phase 07.1: Gallery Cleanup Tool - Context

**Gathered:** 2026-03-06
**Status:** Ready for planning

<domain>
## Phase Boundary

ML-powered cleanup tool that scans all imported images and videos, identifies those containing an appropriate human subject (clear face/body), and moves non-matching media to a `_review/` subfolder. Enables rapid dataset curation from raw media libraries without manual sorting. The tool uses a layered CLIP + InsightFace approach and presents results via a dedicated Cleanup page with review-before-removal UX.

</domain>

<decisions>
## Implementation Decisions

### Detection strategy
- **Layered approach**: CLIP text prompts run first as a fast filter, then InsightFace face detection runs as a second pass on CLIP-positive items
- CLIP uses `CLIPEmbedder.encode_text()` with user-customizable positive/negative prompt lists (smart defaults provided: "photo of a woman", "portrait of a woman" vs "screenshot", "meme", "text graphic", "landscape", "food")
- Items scoring below the CLIP person-detection threshold are rejected early without loading InsightFace
- InsightFace confirms face presence (any human face) — no gender classification used
- **Separate cleanup threshold** from triage threshold (CLIP text-to-image similarity scores are naturally lower ~0.20–0.35 vs triage image-to-image ~0.60–0.90)
- Combined numeric confidence score (0–1.0) merging CLIP similarity and face detection, plus a classification label (keep/review/remove)
- For videos: sample 3 evenly-spaced frames per video via existing `sample_clip_frames()`, use best score
- Anime/illustration content treated equally to real photos — no separate handling

### Classification scope
- **Strict filtering**: only keep images with clear face or body visible
- Back-of-head shots, silhouettes, partial body (hands only) get flagged for removal
- Group photos (multiple people) are kept — still useful for LoRA training
- Non-person content types filtered: screenshots, memes, text graphics, landscapes, food, objects, product shots

### Navigation & page layout
- **Dedicated Cleanup page** at `/cleanup` with its own NavBar item
- Nav order: Gallery > Import > Video > **Cleanup** > Crop > Caption > Triage > Settings
- Workflow starts from Gallery via a "Cleanup" button that redirects to `/cleanup`
- Scan **auto-starts on arrival** when redirected from Gallery — results stream in as items are classified
- Cleanup page can also be visited directly (manual start button available for re-runs)

### Review UX
- **Summary stats bar** at top: "X flagged / Y kept / Z total" with confidence breakdown
- **Thumbnail grid shows only flagged items** (items the system wants to remove) — kept items don't need review
- Each flagged thumbnail shows a confidence score overlay
- **Click to un-flag**: single click on a flagged item rescues it (removes from cleanup, keeps in project)
- Un-flagged items disappear from the grid or get a visual "kept" treatment
- **"Confirm Removal" button** acts on remaining flagged items
- After confirmation: toast notification ("X items moved to _review/") and **redirect to Gallery**
- Progress bar with SSE during scan (follows existing SSE patterns: asyncio.Queue + named events + cancel)
- Scan is cancellable mid-operation — keeps results produced so far

### File handling on removal
- Removed items moved to `{project_dir}/_review/` subfolder — never deleted
- **Sidecar files** (.txt captions, .json metadata) moved alongside their parent image/video
- Removed entries **deleted from manifest.json** so they no longer appear in gallery
- **Audit log** written to `_review/cleanup_log.json` — lists every moved file, original path, classification score, and timestamp

### Claude's Discretion
- CLIP text prompt default lists (positive and negative) — specific wording and number of prompts
- Score combination algorithm (how CLIP similarity and face detection boolean combine into a 0–1 score)
- Cleanup threshold default value (likely ~0.25 for CLIP text similarity)
- SSE event naming for cleanup operations (following existing patterns: `cleanup_progress`, `cleanup_error`, `cleanup_done`)
- Whether to batch InsightFace calls or process one-by-one
- UI styling for the cleanup page (consistent with existing pages)
- How to handle the "Cleanup" button on Gallery page (always visible vs conditional)

</decisions>

<specifics>
## Specific Ideas

- Primary use case is cleaning raw Instagram/social media saves that contain a mix of subject photos, screenshots, memes, food photos, landscapes, and random content
- The "Cleanup" button on Gallery acts as a workflow trigger — it's the entry point, not just a link
- User envisions the pipeline as: Import to Gallery > Video > **Cleanup** (remove irrelevant) > Crop > Caption
- Results should stream in as processed (not wait for full scan to complete)
- False positive rescue should be as frictionless as possible — one click to keep an item

</specifics>

## Existing Code Insights

### Reusable Assets
- `klippbok/triage/embeddings.py`: CLIPEmbedder with `encode_text()`, `encode_image()`, `encode_images()`, `similarity()`, `best_match_score()` — core ML engine for CLIP classification
- `klippbok/services/face_service.py`: `compute_face_embeddings()`, `check_insightface_available()` — face detection layer
- `klippbok/triage/sampler.py`: `sample_clip_frames()` — frame extraction for video analysis
- `klippbok/triage/triage.py`: `organize_clips()` — file move pattern with sidecar handling (`.txt`, `.json`, `.jsonl`)
- `klippbok/services/triage_service.py`: `_embedder` singleton pattern — avoids reloading 600MB CLIP model
- `klippbok/api/routers/triage.py`: SSE background task pattern with asyncio.Queue, cancel endpoints, progress callbacks

### Established Patterns
- SSE for long-running ops: POST starts background task > GET /events/{op_id} streams progress > cancel endpoint
- Module-level singleton for heavy ML models (`_get_or_create_embedder()`)
- `run_in_executor` for CPU-bound ML work (keeps event loop responsive)
- Manifest-driven state tracking (JSON manifests for pipeline communication)
- `organize_clips()` sidecar transfer pattern: `.txt`, `.json`, `.jsonl` extensions

### Integration Points
- GalleryPage needs "Cleanup" button that triggers navigation to `/cleanup`
- NavBar.tsx — add Cleanup nav item between Video and Crop
- App.tsx router — add `/cleanup` route
- `klippbok/services/project_service.py`: `load_manifest()` for reading manifest, manifest writing for entry removal
- appStore needs cleanup-related state (cleanup results, flagged items, un-flagged items)
