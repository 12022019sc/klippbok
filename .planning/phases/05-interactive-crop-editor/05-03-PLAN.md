<objective>
Build the interactive crop editor page -- the signature feature of klippbok. A batch grid of crop cards using react-advanced-cropper with bucket-ratio snapping, zoom/rotate/flip controls, resolution readouts, and auto-crop integration.

Purpose: This is the core value proposition -- no existing tool does bucket-aware batch cropping well. Users crop all selected images simultaneously with real-time feedback on training suitability.
Output: CropPage with BucketSelector, CropCard (per-image cropper + controls), CropReadout, styled with plain CSS.
</objective>

**B. Create CropCard.tsx** -- the per-image interactive crop card. Reference the malcolmrey dataset-prep screenshots for layout.

Props: `{ item: GalleryItem, buckets: [number, number][], isCtrlHeld: boolean, onCropChange: (imageId: string, state: CropState) => void, onExclude: (imageId: string) => void, initialCropState?: CropState }`

Structure:
1. **Header**: filename (truncate to ~30 chars) + original dimensions (e.g. "1920x1080") + quality badge (green "Sharp" or red "Blurry" based on `item.quality_pass`)
2. **Cropper**: `<Cropper>` from react-advanced-cropper with:
   - `ref={cropperRef}` for imperative methods
   - `src={item.full_url}` (full resolution image URL)
   - `stencilProps={{ aspectRatio: isCtrlHeld ? undefined : lockedAR }}` -- dynamic AR (RESEARCH Pattern 1)
   - `onChange` callback: extract coordinates via `cropper.getCoordinates()` (always in image-space per Pitfall 3), update CropReadout, call `onCropChange` with new CropState
   - Import and apply `'react-advanced-cropper/dist/style.css'`
   - Container height: ~300px with overflow hidden (card in the grid)
3. **CropReadout** (below cropper): resolution indicator + AR badge
4. **Controls row** (below readout, matching malcolmrey layout):
   - Left side: Rotate 90 CW button, Rotate 90 CCW button, Flip H button, Flip V button
   - Right side: Zoom slider (`<input type="range">`) tied to `cropperRef.current?.zoomImage(factor)`
   - Rotation: `cropperRef.current?.rotateImage(90)` or `(-90)`. Track cumulative rotation in local state (0/90/180/270).
   - Flip: `cropperRef.current?.flipImage(true, false)` for H, `(false, true)` for V. Track flip state locally.
5. **Footer**: Include (+) / Exclude (x) buttons. Exclude calls `onExclude(item.id)`.

State management within CropCard:
- `lockedAR: number` -- current bucket AR (width/height). Updated on bucket snap.
- When `isCtrlHeld` changes from true to false (CTRL released): read current coordinates, call `snapToNearestBucket`, update `lockedAR`, and programmatically set the cropper's coordinates to match the new AR. Use `cropperRef.current?.setCoordinates()` to adjust.
- Use `useEffect` watching `isCtrlHeld` + coordinates to trigger snap on CTRL release.

Each CropCard has its OWN Cropper instance and ref (anti-pattern warning from RESEARCH.md: never share a single cropper across cards).

**C. Create CropReadout.tsx:**

- Right: AR badge showing the ratio in simplified form (e.g. "1:1", "2:3", "3:4"). Compute by finding GCD and dividing.

**B. Create CropPage.tsx:**

This is the main /crop route page. Layout matches malcolmrey batch grid.

1. **Global controls bar** (sticky top):
   - `<BucketSelector>` on the left
   - "Auto-crop All" button (calls POST /api/v1/crop/auto for all selected images)
   - Image count: "Editing N images"

2. **Scrollable grid** of CropCards:
   - Read `selectedImageIds` from appStore
   - Fetch image details for selected IDs using `useImages()` hook (filter to selected)
   - Generate `buckets` array from `generateBuckets(bucketSize, allowNonSquare)` -- recompute on setting change
   - Responsive CSS grid: `grid-template-columns: repeat(auto-fill, minmax(320px, 1fr))` with max 4 columns (`max-width` or `max-columns` constraint)
   - Each card: `<CropCard item={image} buckets={buckets} isCtrlHeld={isCtrlHeld} ... />`

3. **CTRL key state management** (per RESEARCH.md Pitfall 2 and Pitfall 5):
   - Lift `isCtrlHeld` to CropPage level (NOT per-card -- all cards must share the same CTRL state)
   - `useEffect` with document-level `keydown`/`keyup` listeners for 'Control' key
   - On keydown: `setIsCtrlHeld(true)`
   - On keyup: `setIsCtrlHeld(false)` -- each CropCard reacts to this prop change and snaps its current crop to nearest bucket
   - Cleanup listeners on unmount

4. **Crop state management:**
   - When any CropCard's `onCropChange` fires, update the corresponding entry in `appStore.cropStates` via `setCropState`
   - When a card's exclude button is clicked, call `removeCropState(imageId)` and remove from `selectedImageIds`
   - Initialize crop states: for each selected image that doesn't have a CropState yet, create a default one (center crop at the default bucket AR)

5. **Auto-crop integration:**
   - "Auto-crop All" button: POST to `/api/v1/crop/auto` with all selected image_ids, current bucket_size, allow_non_square
   - On response: for each `AutoCropResult`, update the corresponding CropCard's crop position by calling `cropperRef.current?.setCoordinates({ left, top, width, height })` via the CropState in the store
   - Show loading state during auto-crop ("Detecting subjects...")
   - CROP-09 is satisfied naturally: after auto-crop sets coordinates, user can still drag/resize the crop rectangle

6. **Empty state:** If no images selected (selectedImageIds empty), show message: "No images selected. Go to Gallery to select images for cropping." with a link back to `/`.
