## Summary

Phase 06.1 adds a dedicated Captioning page to the web GUI and wires provider configuration into caption generation. All the heavy backend machinery already exists — CaptionConfig, caption_service.py, openai_compat.py, gemini.py, and the upscale subprocess pattern are production-ready. This phase is primarily:

1. **New UI page** (CaptionPage.tsx) with provider config section, thumbnail strip, and caption workspace
2. **Global config storage** (`~/.klippbok/config.json`) for API keys + provider preferences
3. **JoyCaption subprocess backend** following the exact upscale_service.py pattern
4. **Provider routing extension** in caption_service.py to accept named presets (lm_studio, nanogpt, gemini, joycaption) and resolve them to CaptionConfig instances using global config
5. **Two new API endpoints**: global config GET/PUT (`/api/v1/settings/caption-config`), and model list fetch (`/api/v1/captions/models`)
6. **Nav + routing surgery**: add /caption route, remove Generate Captions from GalleryPage

The generation flow itself (SSE, progress, batch operations) is unchanged — CaptionPage reuses `useCaptionEvents`, calls the same `POST /captions/generate`, and batch ops call the same `POST /captions/batch`. The only new wiring is that the provider + api_key + model + base_url in `CaptionGenerateRequest` are now populated from global config rather than hardcoded or passed ad-hoc.

**Primary recommendation:** Build inside-out — global config service first, then JoyCaption backend, then provider routing, then API endpoints, then UI. All pieces are independently testable.

## Architecture Patterns

### Pattern 1: Global Config Storage (`~/.klippbok/config.json`)

Follows the exact same pattern as `~/.klippbok/profiles/` (custom model profiles). A new service module `klippbok/services/global_config_service.py` owns read/write.

```python
# Source: Codebase pattern from klippbok/config/model_config.py
_USER_KLIPPBOK_DIR = Path.home() / ".klippbok"
_GLOBAL_CONFIG_FILE = _USER_KLIPPBOK_DIR / "config.json"

def load_global_config() -> dict:
    """Load ~/.klippbok/config.json or return empty dict if not found."""
    if _GLOBAL_CONFIG_FILE.exists():
        return json.loads(_GLOBAL_CONFIG_FILE.read_text(encoding="utf-8"))
    return {}

def save_global_config(config: dict) -> None:
    """Persist config to ~/.klippbok/config.json."""
    _USER_KLIPPBOK_DIR.mkdir(parents=True, exist_ok=True)
    _GLOBAL_CONFIG_FILE.write_text(
        json.dumps(config, indent=2, ensure_ascii=False) + "\n",
        encoding="utf-8",
    )
```

**Global config schema** (stored in config.json):
```json
{
  "caption": {
    "provider": "lm_studio",
    "lm_studio_base_url": "http://localhost:1234/v1",
    "lm_studio_model": "",
    "nanogpt_api_key": "",
    "nanogpt_model": "",
    "gemini_api_key": "",
    "gemini_model": "gemini-2.5-flash",
    "joycaption_path": "",
    "custom_prompt": null
  }
}
```

**Key insight:** trigger_word (anchor_word) is NOT stored here — it goes in the per-project manifest under key `"anchor_word"`. The API endpoint for saving trigger word must write to manifest, not global config.

### Pattern 2: JoyCaption Backend (subprocess pattern from upscale_service.py)

```python
# Source: klippbok/services/upscale_service.py — exact structural parallel

def _build_joycaption_paths() -> list[Path]:
    """Candidate JoyCaption venv paths to check."""
    candidates: list[Path] = [
        Path(r"C:\GenAI\Tools\JoyCaption"),
        Path.home() / "GenAI" / "Tools" / "JoyCaption",
    ]
    env_path = os.environ.get("JOYCAPTION_PATH")
    if env_path:
        candidates.append(Path(env_path))
    return candidates

_JOYCAPTION_COMMON_PATHS: list[Path] = _build_joycaption_paths()

def detect_joycaption() -> Path | None:
    """Find JoyCaption venv root at known paths.
    Checks for venv/Scripts/python.exe (Windows) or venv/bin/python (Linux).
    """
    for candidate in _JOYCAPTION_COMMON_PATHS:
        python_candidates = [
            candidate / "venv" / "Scripts" / "python.exe",
            candidate / "venv" / "bin" / "python",
        ]
        if any(p.is_file() for p in python_candidates):
            return candidate
    return None
```

**Communication protocol decision (Claude's discretion):** Use stdout line parsing (same as SeedVR2), not temp file. JoyCaption prints progress to stdout. Pass a simple Python runner script that imports JoyCaption, runs inference, and prints `CAPTION:<text>` on a final line. The stdout reader grabs that line as the result.

Alternative: write to a temp .txt file path passed as `--output`. This avoids stdout parsing complexity. Given that JoyCaption is a single-image operation (not a batch loop), a temp file is simpler: write output to `{tmpdir}/caption.txt`, read after process exits.

**Recommended protocol:** temp file — simpler, more reliable for single-image output:
```python
# Runner: joycaption_runner.py (bundled with klippbok)
# Usage: python joycaption_runner.py <image_path> <output_txt_path> [anchor_word] [custom_prompt]
```

### Pattern 3: Provider Routing in caption_service.py

The existing `caption_image_for_project()` accepts a `CaptionConfig | None`. Extend it with a new helper that maps provider presets to CaptionConfig using global config:

```python
# Source: klippbok/services/caption_service.py

def build_vlm_config_from_global(
    provider: str,  # "lm_studio" | "nanogpt" | "gemini" | "joycaption"
    global_config: dict,
    manifest: dict,
) -> CaptionConfig:
    """Build a CaptionConfig from a named provider preset + global config.

    Args:
        provider: Named provider preset.
        global_config: Loaded from ~/.klippbok/config.json.
        manifest: Project manifest (for anchor_word lookup).

    Returns:
        CaptionConfig ready to pass to caption_image_for_project().
    """
    caption_cfg = global_config.get("caption", {})
    anchor_word = manifest.get("anchor_word")

    if provider == "lm_studio":
        return CaptionConfig(
            provider="openai",
            openai_base_url=caption_cfg.get("lm_studio_base_url", "http://localhost:1234/v1"),
            openai_model=caption_cfg.get("lm_studio_model", ""),
            api_key="lm-studio",  # LM Studio ignores auth header
            anchor_word=anchor_word,
        )
    elif provider == "nanogpt":
        return CaptionConfig(
            provider="openai",
            openai_base_url="https://nano-gpt.com/api",
            openai_model=caption_cfg.get("nanogpt_model", ""),
            api_key=caption_cfg.get("nanogpt_api_key", ""),
            anchor_word=anchor_word,
        )
    elif provider == "gemini":
        return CaptionConfig(
            provider="gemini",
            api_key=caption_cfg.get("gemini_api_key") or os.environ.get("GEMINI_API_KEY", ""),
            gemini_model=caption_cfg.get("gemini_model", "gemini-2.5-flash"),
            anchor_word=anchor_word,
        )
    elif provider == "joycaption":
        # JoyCaption handled separately via subprocess in caption router
        raise ValueError("JoyCaption uses subprocess; use caption_image_joycaption() instead")
    else:
        raise ValueError(f"Unknown provider preset: {provider!r}")
```

### Anti-Patterns to Avoid

- **Don't create a new router file if the endpoint logically belongs to captions.py** — model list and config endpoints can go in captions.py or a new caption_config.py; keep them together
- **Don't store API keys in the manifest** — manifest is project-level, per-project. API keys must go in `~/.klippbok/config.json`
- **Don't send the API key over SSE** — SSE events are not encrypted; config is loaded server-side
- **Don't rebuild the SSE generation flow** — `POST /captions/generate` + `useCaptionEvents` already works; just pass the right provider config
- **Don't add a JoyCaption health check that times out the UI** — run health check async on provider selection change, not blocking the page render

## Common Pitfalls

### Pitfall 1: JoyCaption venv Python on Windows

**What goes wrong:** `venv/Scripts/python.exe` path is Windows-specific. On Linux it's `venv/bin/python`.
**Why it happens:** Copied from SeedVR2 pattern, which already handles both.
**How to avoid:** Mirror `get_seedvr2_python()` exactly — check both paths.
**Warning signs:** `FileNotFoundError` when trying to start JoyCaption subprocess.

### Pitfall 2: LM Studio model list is empty unless a model is loaded

**What goes wrong:** `/v1/models` returns an empty list if LM Studio has no model loaded.
**Why it happens:** LM Studio only reports models it has loaded, not installed models.
**How to avoid:** Show a helpful message "No model loaded in LM Studio" when list is empty. Allow manual text entry as fallback.
**Warning signs:** Model picker dropdown shows empty; generation fails with "model not found".

### Pitfall 3: NanoGPT API key priority

**What goes wrong:** Env var `NANO_GPT_API_KEY` overrides the UI-entered key.
**Why it happens:** Code checks env var first by habit.
**How to avoid:** Per decision: config.json key always wins; env var is ONLY fallback when config has no key.
```python
api_key = caption_cfg.get("nanogpt_api_key") or os.environ.get("NANO_GPT_API_KEY", "")
```

### Pitfall 4: Global config write race condition

**What goes wrong:** Two saves in quick succession corrupt config.json (partial write).
**Why it happens:** No atomic write on Windows; partial writes possible.
**How to avoid:** Write to a temp file, then `os.replace()` atomically. Mirror the manifest write pattern.

### Pitfall 5: anchor_word stored in global config instead of manifest

**What goes wrong:** Trigger word is written to `~/.klippbok/config.json` making it global across projects.
**Why it happens:** Trigger word UI lives in the provider config section (same page as global settings).
**How to avoid:** Trigger word save must call `PUT /api/v1/settings/` or a manifest-specific endpoint. Keep it separate from global config save. Make the save pathway explicit in the plan.

### Pitfall 6: CaptionPage Generate Captions button sends no provider

**What goes wrong:** `POST /captions/generate` sent without provider_preset; backend defaults to booru for NL profiles.
**Why it happens:** Provider config section is collapsed and state not threaded to the generate call.
**How to avoid:** CaptionPage state must hold `activeProvider` and include it in every generate request.

### Pitfall 7: GalleryPage `handleGenerateCaptions` not removed completely

**What goes wrong:** Generate Captions button removed from render, but `captionOperationId` state + `useCaptionEvents` hook + `handleGenerateCaptions` function still in GalleryPage.
**Why it happens:** Incremental removal leaves dead code.
**How to avoid:** Remove all caption generation code from GalleryPage in one task. The caption panel in the lightbox (`CaptionPanel.tsx`) stays.
