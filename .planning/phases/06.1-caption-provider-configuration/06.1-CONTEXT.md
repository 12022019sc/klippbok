# Phase 06.1: Caption Provider Configuration - Context

**Gathered:** 2026-03-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a dedicated Captioning page to the web GUI with provider configuration, model selection, API key management, trigger word/prompt settings, batch tag operations, and a split-view caption workspace. Wire saved config into the Generate Captions flow. Remove the Generate Captions button from the Gallery page — all caption work happens on the Captioning page.

</domain>

<decisions>
## Implementation Decisions

### Provider presets
- Four named providers: **LM Studio**, **NanoGPT**, **Gemini**, **JoyCaption**
- Replicate is NOT included (user doesn't use it)
- LM Studio and NanoGPT both use the `openai_compat` backend with different default URLs:
  - LM Studio: `http://localhost:1234/v1` (local)
  - NanoGPT: `https://nano-gpt.com/api` (hosted, OpenAI-compatible, Bearer token auth)
- Gemini uses existing `gemini` backend
- JoyCaption uses **subprocess** integration (same pattern as SeedVR2/NMKD upscaler):
  - Runs via its own venv at `C:\GenAI\Tools\JoyCaption\venv`
  - Auto-detect install path (check common locations + `JOYCAPTION_PATH` env var), with UI override
  - Model: `fancyfeast/llama-joycaption-beta-one-hf-llava` (4-bit, ~5-6GB VRAM)
- Default provider: **LM Studio** — with a health check to validate it's running before generating
- LM Studio model picker: query `/v1/models` endpoint to show loaded models
- NanoGPT model picker: query `GET /api/v1/models?detailed=true` and filter for vision-capable subscription models

### Captioning page (new nav item)
- New top-level nav item: **Caption** — between Crop and Settings in the navbar
- Nav order reflects the pipeline workflow: Gallery → Crop → Caption → Export (+ Settings)
- **Full caption workspace** layout:
  - Horizontal thumbnail strip at top (gallery view)
  - Selected image preview + caption editor below
- **Collapsible provider config section** at top of page:
  - Shows provider name + summary when collapsed
  - Expands to show all settings: provider dropdown, model picker, API key, base URL, trigger word, custom prompt
- **Generate Captions button** lives on this page (removed from Gallery page)
- **Batch tag operations** (add/remove/replace tag, prepend trigger) have UI controls on this page
- Caption editing happens inline in the workspace (not in the Gallery lightbox)

### API key storage
- Keys stored in **global user config**: `~/.klippbok/config.json` (not per-project)
- Shared across all projects — one place to manage API keys
- API key enterable from the Captioning page UI (masked text field, saved to global config on submit)
- **Priority**: UI-entered key (config.json) always wins; env vars are fallback only when no key in config

### Trigger word & prompt
- Trigger word (anchor_word) is **per-project** — stored in manifest, same trigger regardless of provider
- `use_case` (character/style/motion/object) is **NOT exposed** in UI — stays developer-only, defaults to character
- `custom_prompt` is exposed as an **advanced toggle** (collapsed by default, textarea when expanded) — overrides built-in VLM prompt template
- Trigger word and custom prompt fields live **inside** the collapsible provider config section (all caption settings together)

### Claude's Discretion
- Exact CSS for the caption workspace layout
- Thumbnail strip scroll behavior and selection indicator
- Batch tag operations UI controls layout (buttons, input fields, etc.)
- JoyCaption subprocess communication protocol (stdout parsing vs temp file)
- Health check implementation details (timeout, retry, error display)
- Model list caching strategy for NanoGPT/LM Studio

</decisions>

<specifics>
## Specific Ideas

- The nav bar should reflect the full pipeline workflow: Gallery → Crop → Caption → Export (+ Settings)
- Provider config should be collapsible to maximize workspace area once configured
- LM Studio health check should validate the server is running before attempting to generate
- NanoGPT model list should be filtered to vision-capable models included in the subscription tier
- JoyCaption auto-detection follows the same pattern as SeedVR2/NMKD upscaler detection (check common paths, env var fallback)

</specifics>

<code_context>
## Existing Code Insights

### Reusable Assets
- `CaptionConfig` (caption/models.py): Already has provider, openai_base_url, openai_model, api_key, anchor_word, custom_prompt fields — needs no model changes
- `CaptionGenerateRequest` (api/models.py): Already accepts provider and api_key params
- `caption_service.py`: caption_image_for_project() routes to WD Tagger or VLM backend — just needs correct config passed
- `openai_compat.py`: Backend already works for any OpenAI-compatible endpoint (LM Studio, NanoGPT)
- `SettingsPage.tsx`: Existing settings patterns (select dropdown, text fields, toast notifications)
- `useCaptionEvents.ts`: SSE hook for batch caption progress — reusable on Captioning page
- Upscale subprocess pattern (`upscale_service.py`): Precedent for JoyCaption subprocess integration
- Upscaler detection (`detect_seedvr2()`, `detect_nmkd_siax()`): Pattern for JoyCaption path auto-detection

### Established Patterns
- Settings persistence: manifest.json for per-project, will add ~/.klippbok/config.json for global
- Provider routing: caption_service already routes by style (booru vs NL) — extend to route by provider preset
- SSE progress: Batch operations use asyncio.Queue + EventSourceResponse pattern
- Subprocess backends: upscale_service runs external tools via subprocess, reports progress via SSE

### Integration Points
- NavBar.tsx: Add "Caption" nav item between Crop and Settings
- GalleryPage.tsx: Remove "Generate Captions" button
- App routing: Add /caption route
- Settings router: Add endpoints for global config (API keys)
- Captions router: Wire provider config from global config + per-project manifest into CaptionConfig

</code_context>
