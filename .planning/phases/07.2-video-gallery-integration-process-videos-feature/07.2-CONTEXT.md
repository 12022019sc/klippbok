# Phase 07.2: Video-Gallery Integration (Process Videos Feature) - Context

**Gathered:** 2026-03-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Rewrite the video processing workflow so the Video tab becomes the single, unified hub for all video operations. The current implementation is disconnected — the Gallery "Process Videos" button, the Video tab's Ingest/Scan/Extract tabs, and the separate ProcessVideosPage are three isolated experiences that don't connect. This phase merges them into one coherent flow: a Quick Process default view on the Video tab that runs an automated pipeline (scene detect → split → extract best frames → review → confirm import), with the existing advanced tabs available as a toggle. Extracted frames flow into the gallery via the full image import pipeline, replacing video entries in the manifest.

</domain>

<decisions>
## Implementation Decisions

### Unified architecture
- **Scrap ProcessVideosPage.tsx** and the /process-videos route — everything consolidates onto the Video tab (/video)
- Gallery "Process Videos" button navigates to /video with all or selected videos queued for processing
- SelectionToolbar "Process Videos (N)" button navigates to /video with selected video paths
- **Audit existing backend** before deciding rewrite scope — fix what's broken, rewrite what's unsalvageable
- Both Gallery and Video tab show video items (synced views via same data source) — removing a video from either view removes the file and updates both

### Quick Process (default Video tab view)
- **Default view** when landing on the Video tab — a streamlined automated pipeline
- One "Process Videos" button with smart defaults (16fps, 720p, auto scene threshold)
- Settings accessible via a settings/config option (not blocking the main flow)
- **Auto-detect video type**: long raw videos (>=30s) get scene detection + split; short clips (<30s) get direct frame extraction
- Full pipeline: scene detect → split clips → extract best reference frame per clip → present for review
- **Stage-aware progress**: show current stage name + per-stage progress bar (e.g., "Scene Detection... 3/5 videos" → "Splitting clips... 7/12" → "Extracting frames... 4/7")

### Advanced workflows (toggle/accordion)
- Existing Ingest/Scan/Extract tabs available as an "Advanced" toggle or sub-tabs alongside Quick Process
- These must actually work — currently Extract produces invisible output (frames go to refs/ with no feedback) and Scan shows stats without thumbnails or actionable information
- Fix Extract: show where frames went, present them visually, allow adding to gallery
- Fix Scan: add thumbnails and make the information actionable (not just raw stats)

### Video clip browser on Video tab
- Video tab shows a visual grid of video clips with thumbnails, durations, and play controls
- Synced with main Gallery — same data source, changes propagate to both views without manual refresh
- Click-to-preview opens a lightweight video player
- **Fix video audio**: muted by default, and make the mute button actually functional (currently broken in Gallery lightbox)

### Frame review UX
- **Flat grid** of all extracted frames with source video labels on each thumbnail
- **Click to deselect**: all frames selected by default, click toggles off (dimmed/crossed out). Only selected frames get imported
- **Lightbox on click**: click a frame for larger preview, arrow keys AND scroll wheel to navigate between frames
- **Fix Gallery lightbox too**: add scroll wheel navigation for image browsing (currently only arrow keys work)
- **Quality indicators**: each frame thumbnail shows resolution (WxH) and blur score — reuses existing blur detection

### Error handling
- **Auto-skip failed videos**: if scene detection or extraction fails for a video, skip it and continue processing remaining videos
- **Warning in summary**: after processing, show summary: "5 videos processed, 12 frames extracted, 2 videos had no usable frames" with failed videos listed and reason
- **Cancel cleans up everything**: if user cancels mid-processing, discard all extracted frames (clean slate, no partial results)
- **ffmpeg check at server startup**: if ffmpeg/ffprobe not installed, disable video features entirely and show warning in nav

### Post-confirm flow
- **Confirm**: selected frames imported via full batch_import_images() pipeline (probe, validate, bucket, blur, phash, dedup), video entries removed from manifest
- **Navigate to Gallery** after confirm with success toast: "Imported 12 frames from 5 videos"
- **TanStack Query cache invalidation** on confirm — Gallery auto-refetches, no manual refresh needed
- **Discard**: prompt user "Also remove the source videos from the gallery?" — yes removes both frames and video entries, no keeps videos
- Discarded frame files deleted from refs/ directory

### Claude's Discretion
- Route cleanup: whether to keep /process-videos as redirect or remove entirely
- Backend rewrite scope: determined by audit of existing endpoints
- CSS approach for the redesigned Video tab
- Exact layout of the Advanced toggle (accordion, sub-tabs, or collapsible section)
- Video clip browser grid implementation (reuse MasonryGrid or simpler grid)
- Smart defaults for scene detection threshold and extraction parameters

</decisions>

<specifics>
## Specific Ideas

- The primary frustration is that the Video Pipeline is powerful but completely disconnected from the user experience — extracted frames are invisible, scan shows useless stats, nothing flows into the gallery
- "Process should be fast and efficient, with most of the workflow automated but with options exposed to the user and relevant choices presented"
- Gallery lightbox needs scroll wheel navigation (currently only arrow keys) — applies to both the main Gallery and the frame review lightbox
- Video mute button in Gallery lightbox is broken — needs fixing
- The pipeline should feel like one connected flow: Gallery shows videos → Process on Video tab → Frames appear in Gallery

</specifics>
