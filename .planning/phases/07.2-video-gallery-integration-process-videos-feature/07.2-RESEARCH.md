# Phase 07.2: Video-Gallery Integration (Process Videos Feature) - Research

**Researched:** 2026-03-07
**Domain:** React frontend UX rewrite + Python backend pipeline consolidation
**Confidence:** HIGH

## Summary

This phase consolidates three disconnected video processing experiences (Gallery "Process Videos" button, VideoPage Ingest/Scan/Extract tabs, and the standalone ProcessVideosPage) into a single unified Video tab. The backend infrastructure is already robust -- the video router has process/start, process/events, process/confirm, process/discard endpoints, plus ingest and extract pipelines. The primary work is frontend reorganization: replacing the current VideoPage with a Quick Process default view (automated pipeline), moving existing tabs into an Advanced toggle, and adding a frame review UX with selection/deselection and quality indicators.

The existing codebase provides strong foundations. The SSE pattern (POST start -> GET events -> POST cancel) is well-established across import, ingest, extract, process, cleanup, and triage operations. The CleanupPage's three-state pattern (Setup -> Progress -> Review) is the exact model for the Quick Process flow. The process backend runner (`_run_process`) already extracts frames from manifest video entries and stores results for the confirm/discard flow. The main gaps are: (1) the backend process pipeline lacks scene detection + split stages (it only does direct frame extraction), (2) the frontend review UX has no frame selection/deselection, (3) the lightbox lacks scroll wheel navigation, and (4) the Triage page has no workflow guidance.

**Primary recommendation:** Rewrite VideoPage.tsx as a multi-state component (Quick Process default + Advanced toggle), enhance the backend _run_process to include scene detection + split stages for long videos, and add a frame review grid with toggle-selection UX. Keep all existing SSE hooks and backend infrastructure -- refactor, don't rebuild.

### Anti-Patterns to Avoid
- **Separate SSE hooks per operation type:** The project has many SSE hooks (useIngestEvents, useExtractEvents, useProcessEvents). For Quick Process, reuse useProcessEvents or create ONE new hook -- do not proliferate more hooks
- **Direct fetch in components:** Use TanStack Query for data that needs caching (gallery items). Use direct fetch only for one-shot operations (start/cancel/confirm)
- **Global state for ephemeral data:** Video processing state (operation ID, progress, extracted frames) should be component-local, not in appStore. Only put cross-page data in appStore

## Common Pitfalls

### Pitfall 1: Backend _run_process Only Does Direct Extraction
**What goes wrong:** The current _run_process backend runner skips scene detection and splitting. It directly extracts a reference frame from each video file via extract_reference_image(). For long raw videos (>=30s), this produces one frame from the whole video rather than splitting into scenes first.
**Why it happens:** ProcessVideosPage was designed for short clips already in the manifest, not raw footage.
**How to avoid:** Enhance _run_process (or create a new _run_quick_process) to add scene detection + split stages before extraction. Use the video duration to auto-detect: >=30s gets full pipeline, <30s gets direct extraction.
**Warning signs:** Only one frame extracted from a 5-minute video.

### Pitfall 2: Extract Output Goes to refs/ With No Gallery Integration
**What goes wrong:** The existing Extract tab extracts frames to refs/ directory but they never appear in the Gallery. The frames are invisible to the user.
**Why it happens:** extract_frames() writes PNGs to refs/ but never calls batch_import_images() to add them to the manifest.
**How to avoid:** The Quick Process confirm flow already calls batch_import_images(refs_dir, project_dir). Ensure the Advanced Extract tab also offers "Import to Gallery" after extraction.

### Pitfall 3: SSE Event Name Collision
**What goes wrong:** Using "error" as an SSE event name collides with EventSource's built-in error event, causing the connection to close unexpectedly.
**Why it happens:** EventSource reserves "error" as a built-in event type.
**How to avoid:** Follow established naming: process_progress, process_done, process_error (prefixed names). This pattern is already used consistently -- just don't deviate.

### Pitfall 4: Scroll Wheel on Lightbox Conflicts with Zoom
**What goes wrong:** Adding a wheel event listener for slide navigation conflicts with the browser's default zoom behavior or with the lightbox's own zoom plugin.
**Why it happens:** The wheel event is used for multiple purposes.
**How to avoid:** Use the controller ref approach documented by yet-another-react-lightbox. Add a wheel handler that calls controller.prev()/next() and calls e.preventDefault() to prevent zoom. Do NOT enable the Zoom plugin simultaneously.

### Pitfall 5: Race Condition on Cancel Cleanup
**What goes wrong:** If the user cancels mid-processing, extracted frames in refs/ are not cleaned up, leaving partial results.
**Why it happens:** The backend task is cancelled via asyncio but doesn't clean up files.
**How to avoid:** Track all extracted frame paths during processing. On cancel, the cancel endpoint (or the frontend) should call the discard endpoint to delete partial frames. Alternatively, use a temporary directory for in-progress extraction and only move to refs/ on completion.

### Pitfall 6: Video Mute Button Non-Functional
**What goes wrong:** The video element in ImageLightbox.tsx renders with `autoPlay` but no `muted` attribute, and no mute toggle UI.
**Why it happens:** The video render in ImageLightbox just renders a bare `<video>` element.
**How to avoid:** Add `muted` attribute to the video element, and add a mute/unmute button overlay. Use local state to toggle the muted prop.

### Example 1: Scroll Wheel Navigation for Lightbox
```typescript
// Source: yet-another-react-lightbox docs (controller ref approach)
import Lightbox, { LightboxExternalProps } from 'yet-another-react-lightbox'
import { useRef, useEffect } from 'react'

function ImageLightbox({ items, currentIndex, open, onClose }: Props) {
  const controllerRef = useRef<any>(null)

  useEffect(() => {
    if (!open) return
    function handleWheel(e: WheelEvent) {
      e.preventDefault()
      if (e.deltaY > 0) {
        controllerRef.current?.next()
      } else {
        controllerRef.current?.prev()
      }
    }
    window.addEventListener('wheel', handleWheel, { passive: false })
    return () => window.removeEventListener('wheel', handleWheel)
  }, [open])

  return (
    <Lightbox
      open={open}
      close={onClose}
      slides={slides}
      index={currentIndex}
      controller={{ ref: controllerRef }}
      // ... existing render props
    />
  )
}
```

### Example 3: Frame Review Grid with Toggle Selection
```typescript
// Pattern: Flat grid with click-to-deselect (all selected by default)
interface FrameReviewProps {
  frames: ExtractedFrame[]
  onSelectionChange: (selected: Set<string>) => void
}

function FrameReviewGrid({ frames, onSelectionChange }: FrameReviewProps) {
  const [deselected, setDeselected] = useState<Set<string>>(new Set())

  function toggleFrame(framePath: string) {
    setDeselected(prev => {
      const next = new Set(prev)
      if (next.has(framePath)) next.delete(framePath)
      else next.add(framePath)
      // Notify parent: selected = all minus deselected
      const selected = new Set(frames.map(f => f.frame_path).filter(p => !next.has(p)))
      onSelectionChange(selected)
      return next
    })
  }

  return (
    <div className="frame-review-grid">
      {frames.map(frame => (
        <div
          key={frame.frame_path}
          className={`frame-card ${deselected.has(frame.frame_path) ? 'deselected' : ''}`}
          onClick={() => toggleFrame(frame.frame_path)}
        >
          <img src={`/api/v1/video/process/frame?path=${encodeURIComponent(frame.frame_path)}`} />
          <span className="frame-label">{frame.video_path.split('/').pop()}</span>
          <span className="frame-quality">{frame.width}x{frame.height} | blur: {frame.blur_score}</span>
        </div>
      ))}
    </div>
  )
}
```

## Open Questions

1. **Scene detection for short clips in manifest**
   - What we know: Videos in the manifest can be both raw footage and pre-cut clips
   - What's unclear: Should we use duration as the sole heuristic (>=30s), or also check for existing scene boundaries?
   - Recommendation: Duration-based heuristic is sufficient. The user's CONTEXT says >=30s gets scene detection, <30s gets direct extraction. Trust the user's decision.

2. **Confirm with selective frame import**
   - What we know: Current confirm endpoint imports ALL frames from refs/ via batch_import_images(refs_dir)
   - What's unclear: How to import only selected frames (user deselects some in review)
   - Recommendation: Before calling confirm, move deselected frames out of refs/ (or delete them), then call existing batch_import_images(refs_dir). Alternatively, enhance confirm to accept a list of frame paths and only import those.

3. **Temporary extraction directory vs refs/**
   - What we know: Current pipeline extracts to refs/, cancel leaves orphan files
   - What's unclear: Should we use a temp directory to enable clean cancel?
   - Recommendation: Use a temporary subdirectory (e.g., refs/.processing-{op_id}/) during extraction. On confirm, move to refs/ then import. On cancel, delete the temp directory. This is the cleanest approach for the "cancel cleans up everything" requirement.
